## 4. 契约变更 <!-- 必填（涉及数据结构时） -->

**要求：字段级，不能只写「调整了用户表」**

### 4.1 数据模型
```sql
-- 变更：users 表新增 2 列
ALTER TABLE users ADD COLUMN last_login_at DATETIME NULL COMMENT '最后登录时间';
ALTER TABLE users ADD COLUMN failed_attempts INT NOT NULL DEFAULT 0;
```
| 字段 | 类型 | 可空 | 默认 | 说明 | 迁移方式 |
|---|---|---|---|---|---|
| last_login_at | DATETIME | 是 | NULL | ... | 新增列，无需回填 |
| failed_attempts | INT | 否 | 0 | ... | 新增列，默认值满足存量数据 |

### 4.2 接口
| 方法 | 路径 | 鉴权 | 请求体 | 成功响应 | 失败响应 |
|---|---|---|---|---|---|
| POST | `/api/auth/login` | 否 | `{username, password}` | `200 {token, expires_at}` | `401 {error:"INVALID_CREDENTIALS"}` / `423 {error:"ACCOUNT_LOCKED"}` |

**错误码全表**（接手方实现时照抄，不要自己编）
| code | HTTP | 触发条件 |
|---|---|---|
| INVALID_CREDENTIALS | 401 | 用户名或密码错误 |
| ACCOUNT_LOCKED | 423 | 连续失败 ≥ 5 次 |

### 4.3 配置项
| key | 默认值 | 说明 |
|---|---|---|
| `AUTH_MAX_FAILED_ATTEMPTS` | `5` | 锁定阈值 |

## 5. 任务卡 <!-- 必填，本模板最重要的部分 -->

> 规则：每张卡必须**可独立完成、可独立验证**。卡与卡之间只通过「已完成状态」耦合。
> 禁止在一张卡里塞多个目标。
>
> **四条硬约束（冷读实测出来的，违反任何一条都会被陌生执行者打回）**
>
> 1. **要照抄的，就得内嵌**：凡是「逐字搬移 / 复制这段实现 / 照抄范式」，被复制对象必须以完整代码块写在卡的「需要的上下文」里。只给 `文件:行号` = 没写。
> 2. **命令必须可原样执行**：不出现未定义的 shell 变量（要先给 `make_key() { … }` 这类定义段）、不写机器绝对路径的解释器（统一 `uv run python` / `pnpm`）、管道里的断言能给出期望输出。
> 3. **依赖真环境的卡标 `[ENV]`**：起服务、LLM 凭据、内网 DB 都算。并在 §6.2 写清「环境不具备时停在卡前并如实报告，禁止伪造输出」。
> 4. **卡里不许出现 `...` 省略号式的待补签名**：类/函数构造参数、字段清单、枚举值要么写全，要么明确「由 T0 实测回填」并给出实测命令。
